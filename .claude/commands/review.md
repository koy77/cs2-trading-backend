# /review — ревью изменений

Область ревью: $ARGUMENTS. Если пусто — `git diff main...HEAD` (текущая ветка против `main`).

## 1. Проверки (упавшая проверка — blocker, ревью «зелёным» быть не может)

- Стиль (Pint): `./vendor/bin/pint --test` (не `make lint` — там режим `--dirty`, он правит файлы)
- PHPCS (PSR-12): `make phpcs` → `./vendor/bin/phpcs --standard=phpcs.xml`
- Статанализ: `make stan` → `./vendor/bin/phpstan analyse --no-progress`
- Тесты: `make test` → `php artisan test`

## 2. Дифф

Прочитай дифф целиком, затем — окружающий код затронутых файлов (не ревьюй по обрывкам).

## 3. Чеклист (обязательные пункты)

- [ ] **Гонки и транзакции**: границы транзакций, atomic claim, локи/мьютексы, unique-индексы;
      поведение при параллельных запросах и повторных вызовах.
- [ ] **Идемпотентность**: повторная доставка вебхуков, ретраи консьюмеров, `Idempotency-Key`, дедуп.
- [ ] **N+1 и запросы**: eager loading, индексы под WHERE/ORDER BY, пагинация; для горячего запроса — EXPLAIN.
- [ ] **Безопасность**: валидация входа (FormRequest), HMAC/подпись и окно timestamp, секреты,
      raw SQL, mass assignment.
- [ ] **Тесты**: новые инварианты закрыты тестами (включая concurrency и негативные), ассерты осмысленные.

## 4. Формат вывода

Каждое замечание: severity (blocker / major / minor) → `file:line` → суть → конкретное исправление.
Сначала blockers. «Вкусовщину» — отдельным блоком и без давления. Ответственность за мердж — на авторе PR.
